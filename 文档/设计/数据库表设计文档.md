## 一、概述

### 1.1 设计目标

本文档定义了商品交易系统的数据库表结构，包括：
- 用户模块：用户账户、充值记录
- 商家模块：商品库存、商家账户、收款记录、对账记录
- 交易模块：订单、订单项
- 辅助模块：领域事件记录、异常记录

### 1.2 设计原则

1. **规范化设计**：遵循第三范式（3NF），避免数据冗余
2. **性能优化**：合理设计索引，提升查询性能
3. **扩展性**：预留扩展字段，支持未来功能迭代
4. **一致性**：使用乐观锁（version字段）保证并发安全
5. **可追溯**：所有表包含created_at和updated_at时间戳

### 1.3 数据库选型

- **数据库**：MySQL 8.0
- **字符集**：utf8mb4（支持emoji等特殊字符）
- **存储引擎**：InnoDB（支持事务、行锁、外键）
- **时区**：UTC（统一时区，应用层转换）

## 三、详细表设计

### 3.1 用户模块

#### 3.1.1 user_account（用户账户表）

**表说明**：存储用户预存账户信息，包括余额、货币类型等。每个用户一条记录。

**建表语句**：
```sql
CREATE TABLE user_account (
    user_id BIGINT PRIMARY KEY COMMENT '用户ID',
    balance DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '账户余额（单位：元）',
    currency VARCHAR(3) NOT NULL DEFAULT 'CNY' COMMENT '货币类型（ISO 4217标准：CNY=人民币）',
    version INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号（用于并发控制）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户账户表';
```

**字段说明**：

| 字段名 | 数据类型 | 长度 | 必填 | 默认值 | 说明 |
|-------|---------|------|------|--------|------|
| user_id | BIGINT | - | ✅ | - | 用户ID（主键），全局唯一标识 |
| balance | DECIMAL | 10,2 | ✅ | 0.00 | 账户余额，精度2位小数，范围0.00~99999999.99 |
| currency | VARCHAR | 3 | ✅ | CNY | 货币类型，目前仅支持CNY（人民币） |
| version | INT | - | ✅ | 0 | 乐观锁版本号，每次更新+1，防止并发冲突 |
| created_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 记录创建时间 |
| updated_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 记录最后更新时间，自动更新 |

**索引说明**：

| 索引名 | 索引类型 | 字段 | 说明 |
|-------|---------|------|------|
| PRIMARY | 主键索引 | user_id | 聚簇索引，唯一标识用户 |
| idx_user_id | 普通索引 | user_id | 加速按用户ID查询（冗余索引，可选） |

**业务规则**：
- 用户首次充值时自动创建账户记录
- 余额不能为负数（通过应用层校验 + SQL条件保证）
- 使用乐观锁防止并发扣款冲突

**示例数据**：
```sql
INSERT INTO user_account (user_id, balance, currency, version) 
VALUES (1001, 500.00, 'CNY', 0);
```

#### 3.1.2 recharge_record（充值记录表）

**表说明**：记录用户充值流水，用于账务对账和问题追溯。每条充值记录对应一次充值操作。

**建表语句**：
```sql
CREATE TABLE recharge_record (
    recharge_id VARCHAR(32) PRIMARY KEY COMMENT '充值ID（UUID去掉横线，大写）',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    amount DECIMAL(10,2) NOT NULL COMMENT '充值金额（单位：元）',
    request_id VARCHAR(64) NOT NULL UNIQUE COMMENT '请求ID（幂等性保证，客户端生成）',
    status VARCHAR(20) NOT NULL DEFAULT 'SUCCESS' COMMENT '充值状态（SUCCESS=成功, FAILED=失败）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_user_id (user_id),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='充值记录表';
```

**字段说明**：

| 字段名 | 数据类型 | 长度 | 必填 | 默认值 | 说明 |
|-------|---------|------|------|--------|------|
| recharge_id | VARCHAR | 32 | ✅ | - | 充值ID（主键），格式：RCH_YYYYMMDD_XXXXX或UUID |
| user_id | BIGINT | - | ✅ | - | 用户ID，关联user_account.user_id |
| amount | DECIMAL | 10,2 | ✅ | - | 充值金额，精度2位小数，范围0.01~10000.00 |
| request_id | VARCHAR | 64 | ✅ | - | 请求ID（唯一索引），客户端生成，保证幂等性 |
| status | VARCHAR | 20 | ✅ | SUCCESS | 充值状态：SUCCESS（成功）、FAILED（失败） |
| created_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 充值时间 |

**索引说明**：

| 索引名 | 索引类型 | 字段 | 说明 |
|-------|---------|------|------|
| PRIMARY | 主键索引 | recharge_id | 聚簇索引，唯一标识充值记录 |
| uk_request_id | 唯一索引 | request_id | 保证幂等性，防止重复充值 |
| idx_user_id | 普通索引 | user_id | 加速按用户ID查询充值记录 |
| idx_created_at | 普通索引 | created_at | 加速按时间范围查询 |

**业务规则**：
- request_id由客户端生成，保证全局唯一
- 相同request_id的重复请求直接返回上次结果（幂等性）
- 充值成功后立即更新user_account.balance

**示例数据**：
```sql
INSERT INTO recharge_record (recharge_id, user_id, amount, request_id, status) 
VALUES ('RCH_20260502_00001', 1001, 100.00, 'REQ_20260502_001', 'SUCCESS');
```

### 3.2 商家模块

#### 3.2.1 product_inventory（商品库存表）

**表说明**：管理商品库存信息，包括SKU、价格、库存数量、已售数量等。同一商家下SKU唯一。

**建表语句**：
```sql
CREATE TABLE product_inventory (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID（自增）',
    sku VARCHAR(64) NOT NULL COMMENT 'SKU编码（Stock Keeping Unit）',
    merchant_id BIGINT NOT NULL COMMENT '商家ID',
    stock_quantity INT NOT NULL DEFAULT 0 COMMENT '库存数量（可售数量）',
    price DECIMAL(10,2) NOT NULL COMMENT '商品单价（单位：元）',
    sold_quantity INT NOT NULL DEFAULT 0 COMMENT '已售数量',
    version INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号（用于并发控制）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE KEY uk_merchant_sku (merchant_id, sku),
    INDEX idx_merchant_id (merchant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='商品库存表';
```

**字段说明**：

| 字段名 | 数据类型 | 长度 | 必填 | 默认值 | 说明 |
|-------|---------|------|------|--------|------|
| id | BIGINT | - | ✅ | 自增 | 主键ID，自增长 |
| sku | VARCHAR | 64 | ✅ | - | SKU编码，格式：^[A-Z0-9_]+$，如IPHONE_15_PRO_256G |
| merchant_id | BIGINT | - | ✅ | - | 商家ID，标识商品所属商家 |
| stock_quantity | INT | - | ✅ | 0 | 库存数量（可售数量），范围0~999999 |
| price | DECIMAL | 10,2 | ✅ | - | 商品单价，精度2位小数，范围0.01~999999.99 |
| sold_quantity | INT | - | ✅ | 0 | 已售数量，累计销售数量 |
| version | INT | - | ✅ | 0 | 乐观锁版本号，每次更新+1，防止超卖 |
| created_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 记录创建时间 |
| updated_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 记录最后更新时间，自动更新 |

**索引说明**：

| 索引名 | 索引类型 | 字段 | 说明 |
|-------|---------|------|------|
| PRIMARY | 主键索引 | id | 聚簇索引，自增主键 |
| uk_merchant_sku | 唯一索引 | merchant_id, sku | 联合唯一索引，保证同一商家下SKU唯一 |
| idx_merchant_id | 普通索引 | merchant_id | 加速按商家ID查询商品列表 |

**业务规则**：
- SKU格式规范：大写字母+数字+下划线（正则：`^[A-Z0-9_]+$`）
- 同一商家下SKU唯一（通过联合唯一索引保证）
- 库存不足时无法下单（stock_quantity >= 购买数量）
- 使用乐观锁防止超卖（version字段）
- 添加库存时，如果SKU已存在则累加stock_quantity

**示例数据**：
```sql
INSERT INTO product_inventory (sku, merchant_id, stock_quantity, price, sold_quantity, version) 
VALUES ('IPHONE_15_PRO_256G', 2001, 100, 8999.00, 0, 0);
```

#### 3.2.2 merchant_account（商家账户表）

**表说明**：存储商家账户信息，包括当前余额和累计收入。每个商家一条记录。

```sql
CREATE TABLE merchant_account (
    merchant_id BIGINT PRIMARY KEY COMMENT '商家ID',

    version INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号（用于并发控制）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_merchant_id (merchant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='商家账户表';
```

**字段说明**：

| 字段名 | 数据类型 | 长度 | 必填 | 默认值 | 说明 |
|-------|---------|------|------|--------|------|
| merchant_id | BIGINT | - | ✅ | - | 商家ID（主键），全局唯一标识 |
| balance | DECIMAL | 10,2 | ✅ | 0.00 | 当前余额，精度2位小数，可提现金额 |
| total_income | DECIMAL | 10,2 | ✅ | 0.00 | 累计收入，历史总收入（只增不减） |
| currency | VARCHAR | 3 | ✅ | CNY | 货币类型，目前仅支持CNY（人民币） |
| version | INT | - | ✅ | 0 | 乐观锁版本号，每次更新+1，防止并发冲突 |
| created_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 记录创建时间 |
| updated_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 记录最后更新时间，自动更新 |

**索引说明**：

| 索引名 | 索引类型 | 字段 | 说明 |
|-------|---------|------|------|
| PRIMARY | 主键索引 | merchant_id | 聚簇索引，唯一标识商家 |
| idx_merchant_id | 普通索引 | merchant_id | 加速按商家ID查询（冗余索引，可选） |

**业务规则**：
- 商家首次收款时自动创建账户记录
- 每笔订单完成后，balance和total_income同时增加
- 使用乐观锁防止并发收款冲突

**示例数据**：
```sql
INSERT INTO merchant_account (merchant_id, balance, total_income, currency, version) 
VALUES (2001, 8999.00, 8999.00, 'CNY', 0);
```

```sql
CREATE TABLE merchant_credit_record (

    INDEX idx_created_at (created_at)

```

**字段说明**：

| 字段名 | 数据类型 | 长度 | 必填 | 默认值 | 说明 |
|-------|---------|------|------|--------|------|

| merchant_id | BIGINT | - | ✅ | - | 商家ID，关联merchant_account.merchant_id |
| amount | DECIMAL | 10,2 | ✅ | - | 收款金额，精度2位小数 |
| order_id | VARCHAR | 32 | ✅ | - | 订单ID，关联orders.order_id |
| created_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 收款时间 |

**索引说明**：

| 索引名 | 索引类型 | 字段 | 说明 |
|-------|---------|------|------|

| idx_merchant_id | 普通索引 | merchant_id | 加速按商家ID查询收款记录 |
| idx_order_id | 普通索引 | order_id | 加速按订单ID查询收款记录 |
| idx_created_at | 普通索引 | created_at | 加速按时间范围查询（对账使用） |

**业务规则**：
- 订单完成后自动创建收款记录
- 收款金额 = 订单总金额

**示例数据**：
```sql
INSERT INTO merchant_credit_record (credit_id, merchant_id, amount, order_id) 
VALUES ('CRT_20260502_00001', 2001, 8999.00, 'ORD_20260502_001');
```

#### 3.2.4 settlement_record（对账记录表）

**表说明**：记录每日对账结果，对比销售总额和收款总额，确保账务一致。每个商家每天一条记录。

**建表语句**：
```sql
CREATE TABLE settlement_record (
    settlement_id VARCHAR(32) PRIMARY KEY COMMENT '对账ID（UUID去掉横线，大写）',
    merchant_id BIGINT NOT NULL COMMENT '商家ID',
    settlement_date DATE NOT NULL COMMENT '对账日期（自然日）',
    total_sales DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '销售总额（单位：元）',
    total_received DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '收款总额（单位：元）',
    difference DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '差异金额（销售总额 - 收款总额）',
    status VARCHAR(20) NOT NULL DEFAULT 'MATCHED' COMMENT '对账状态（MATCHED=一致, MISMATCHED=不一致）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    UNIQUE KEY uk_merchant_date (merchant_id, settlement_date),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='对账记录表';
```

**字段说明**：

| 字段名 | 数据类型 | 长度 | 必填 | 默认值 | 说明 |
|-------|---------|------|------|--------|------|
| settlement_id | VARCHAR | 32 | ✅ | - | 对账ID（主键），格式：STL_YYYYMMDD_XXXXX或UUID |
| merchant_id | BIGINT | - | ✅ | - | 商家ID，关联merchant_account.merchant_id |
| settlement_date | DATE | - | ✅ | - | 对账日期（自然日），格式：YYYY-MM-DD |
| total_sales | DECIMAL | 10,2 | ✅ | 0.00 | 销售总额，从order_item统计 |
| total_received | DECIMAL | 10,2 | ✅ | 0.00 | 收款总额，从merchant_credit_record统计 |
| difference | DECIMAL | 10,2 | ✅ | 0.00 | 差异金额 = total_sales - total_received |
| status | VARCHAR | 20 | ✅ | MATCHED | 对账状态：MATCHED（一致）、MISMATCHED（不一致） |
| created_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 对账时间 |

**索引说明**：

| 索引名 | 索引类型 | 字段 | 说明 |
|-------|---------|------|------|
| PRIMARY | 主键索引 | settlement_id | 聚簇索引，唯一标识对账记录 |
| uk_merchant_date | 唯一索引 | merchant_id, settlement_date | 联合唯一索引，保证每个商家每天只有一条对账记录 |
| idx_created_at | 普通索引 | created_at | 加速按时间范围查询 |

**业务规则**：
- 每天凌晨02:00自动执行对账任务
- 对账日期为自然日（00:00:00 - 23:59:59）
- 对账容忍度：0.00元（必须完全一致）
- 不一致时status=MISMATCHED，记录告警日志
- 支持手动重新对账

**示例数据**：
```sql
INSERT INTO settlement_record (settlement_id, merchant_id, settlement_date, total_sales, total_received, difference, status) 
VALUES ('STL_20260502_00001', 2001, '2026-05-01', 8999.00, 8999.00, 0.00, 'MATCHED');
```

### 3.3 交易模块

#### 3.3.1 orders（订单表）

**表说明**：存储订单主信息，包括订单ID、用户ID、商家ID、订单状态、总金额等。

**建表语句**：
```sql
CREATE TABLE orders (
    order_id VARCHAR(32) PRIMARY KEY COMMENT '订单ID（UUID去掉横线，大写）',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    merchant_id BIGINT NOT NULL COMMENT '商家ID',
    status VARCHAR(20) NOT NULL DEFAULT 'CREATED' COMMENT '订单状态（CREATED=已创建, COMPLETED=已完成, FAILED=失败）',
    total_amount DECIMAL(10,2) NOT NULL COMMENT '订单总金额（单位：元）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    completed_at DATETIME DEFAULT NULL COMMENT '完成时间',
    failure_reason VARCHAR(500) DEFAULT NULL COMMENT '失败原因（status=FAILED时填写）',
    INDEX idx_user_id (user_id),
    INDEX idx_merchant_id (merchant_id),
    INDEX idx_created_at (created_at),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='订单表';
```

**字段说明**：

| 字段名 | 数据类型 | 长度 | 必填 | 默认值 | 说明 |
|-------|---------|------|------|--------|------|
| order_id | VARCHAR | 32 | ✅ | - | 订单ID（主键），格式：ORD_YYYYMMDD_XXXXX或UUID |
| user_id | BIGINT | - | ✅ | - | 用户ID，关联user_account.user_id |
| merchant_id | BIGINT | - | ✅ | - | 商家ID，关联merchant_account.merchant_id |
| status | VARCHAR | 20 | ✅ | CREATED | 订单状态：CREATED（已创建）、COMPLETED（已完成）、FAILED（失败） |
| total_amount | DECIMAL | 10,2 | ✅ | - | 订单总金额，精度2位小数 |
| created_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 订单创建时间 |
| completed_at | DATETIME | - | ❌ | NULL | 订单完成时间（status=COMPLETED时填写） |
| failure_reason | VARCHAR | 500 | ❌ | NULL | 失败原因（status=FAILED时填写） |

**索引说明**：

| 索引名 | 索引类型 | 字段 | 说明 |
|-------|---------|------|------|
| PRIMARY | 主键索引 | order_id | 聚簇索引，唯一标识订单 |

**业务规则**：
- 订单状态流转：CREATED → COMPLETED 或 CREATED → FAILED
- COMPLETED和FAILED为终态，不可再流转
- 订单创建时status=CREATED，异步处理完成后更新为COMPLETED或FAILED
- 失败时必须填写failure_reason


#### 3.4.1 domain_event_record（领域事件记录表）

**表说明**：记录领域事件的发布和处理状态，用于事件重试和追踪。支持事件持久化，防止应用重启导致事件丢失。

```sql
    status VARCHAR(20) NOT NULL DEFAULT 'PENDING' COMMENT '处理状态（PENDING=待处理, PROCESSED=已处理）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    processed_at DATETIME DEFAULT NULL COMMENT '处理时间',
    INDEX idx_status (status),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='领域事件记录表';
```

**字段说明**：

| 字段名 | 数据类型 | 长度 | 必填 | 默认值 | 说明 |
|-------|---------|------|------|--------|------|
| event_id | VARCHAR | 32 | ✅ | - | 事件ID（主键），UUID格式 |
| event_type | VARCHAR | 64 | ✅ | - | 事件类型，如OrderCreatedEvent、UserBalanceDeductedEvent |
| payload | TEXT | - | ✅ | - | 事件内容，JSON格式序列化 |
| status | VARCHAR | 20 | ✅ | PENDING | 处理状态：PENDING（待处理）、PROCESSED（已处理） |
| created_at | DATETIME | - | ✅ | CURRENT_TIMESTAMP | 事件创建时间 |
| processed_at | DATETIME | - | ❌ | NULL | 事件处理完成时间 |

**索引说明**：

| 索引名 | 索引类型 | 字段 | 说明 |
|-------|---------|------|------|
| PRIMARY | 主键索引 | event_id | 聚簇索引，唯一标识事件 |
| idx_status | 普通索引 | status | 加速查询待处理事件（定时重发使用） |
| idx_created_at | 普通索引 | created_at | 加速按时间范围查询 |

**业务规则**：
- 发布事件前先插入记录，status=PENDING

- 定时任务扫描status=PENDING且超过5分钟的事件，进行重发

**示例数据**：

### 5.2 索引设计原则

1. **主键索引**：所有表必须有主键，优先使用自增ID或UUID
2. **唯一索引**：用于保证业务唯一性（如request_id、merchant_id+sku）
3. **普通索引**：用于加速查询，根据查询频率和选择性决定
4. **联合索引**：遵循最左前缀原则，将高选择性字段放在前面
5. **覆盖索引**：尽量让索引包含查询所需的所有字段，减少回表

| 类型 | 说明 | 使用场景 |

**VARCHAR长度选择**：
- VARCHAR(32)：UUID去掉横线后的长度

- 数据库统一使用UTC时区
- 应用层根据用户时区转换显示

### 6.4 特殊字段说明

#### version（乐观锁版本号）

**用途**：防止并发更新冲突

**使用方式**：
```sql
-- 查询时获取version
SELECT version FROM user_account WHERE user_id = 1001;

-- 更新时检查version
UPDATE user_account 
SET balance = balance - 100.00, version = version + 1 
WHERE user_id = 1001 AND version = 5;

-- 如果affected_rows = 0，说明被其他事务修改，需要重试
```

**适用表**：
- user_account
- product_inventory
- merchant_account

**用途**：防止重复提交

**生成方式**：客户端生成UUID或雪花算法ID

```java
try {

    return getPreviousResult(requestId);
```

## 七、性能优化建议

### 7.1 索引优化

1. **避免过多索引**：每个索引都会降低写性能，只创建必要的索引
2. **定期分析索引使用情况**：使用`SHOW INDEX`和慢查询日志
3. **删除无用索引**：长期未使用的索引应及时删除

---

### 7.2 查询优化

1. **避免SELECT ***：只查询需要的字段
2. **使用分页查询**：大数据量时使用LIMIT OFFSET
3. **批量操作**：批量插入/更新减少网络开销

**示例**：
```sql
-- ✅ 推荐：只查询需要的字段
SELECT user_id, balance FROM user_account WHERE user_id = 1001;

-- ❌ 不推荐：查询所有字段
SELECT * FROM user_account WHERE user_id = 1001;

-- ✅ 推荐：分页查询
SELECT * FROM orders WHERE user_id = 1001 ORDER BY created_at DESC LIMIT 10 OFFSET 0;
```

---

### 7.3 分区策略（未来扩展）

当单表数据量超过1000万时，考虑分区：

**按时间分区**：
- orders表：按月分区
- recharge_record表：按月分区
- merchant_credit_record表：按月分区

**分区示例**：
```sql
ALTER TABLE orders 
PARTITION BY RANGE (YEAR(created_at) * 100 + MONTH(created_at)) (
    PARTITION p202601 VALUES LESS THAN (202602),
    PARTITION p202602 VALUES LESS THAN (202603),
    ...
);
```

## 八、数据安全与备份

### 8.1 数据加密

**敏感字段加密**：
- 当前版本无敏感字段
- 未来如有用户密码，使用BCrypt加密
- 如有身份证号等，使用AES加密

---

### 8.2 备份策略

**全量备份**：
- 频率：每天凌晨03:00
- 保留周期：30天
- 工具：mysqldump或Percona XtraBackup

**增量备份**：
- 频率：每小时
- 保留周期：7天
- 工具：MySQL Binlog

**备份验证**：
- 每周进行一次恢复测试
- 验证备份文件完整性

---

### 8.3 灾难恢复

**RPO（恢复点目标）**：≤ 1小时
**RTO（恢复时间目标）**：≤ 30分钟

**恢复步骤**：
1. 停止应用服务
2. 恢复最近的全量备份
3. 回放Binlog到故障点
4. 验证数据完整性
5. 启动应用服务

## 九、附录

### A. 命名规范

**表名**：
- 小写字母+下划线
- 使用复数形式（如orders、users）
- 清晰表达业务含义

**字段名**：
- 小写字母+下划线
- 避免使用保留字（如order、key）
- 主键统一命名为{id}_id或id
- 外键命名为{关联表}_id

**索引名**：
- 主键索引：PRIMARY
- 唯一索引：uk_{字段名}或uk_{字段1}_{字段2}
- 普通索引：idx_{字段名}
