## 一、业务与需求分析

### 1.1 业务背景

本系统是一个面向技术面试的商品交易演示系统，需要在保证功能完整性的同时，展示**高并发处理能力**和**领域驱动设计水平**。采用**Spring Event事件驱动架构**实现领域间解耦，通过**本地事务+事件补偿**保证数据一致性。

**产品定位**：技术演示项目（高并发场景优化版）  
**核心目标**：展示DDD设计、事件驱动架构、高并发处理能力  
**适用场景**：技术面试、架构评审

### 1.2 用户角色

| 角色 | 描述 | 核心诉求 |
|-----|------|---------|
| 普通用户 | 购买商品的用户 | 充值便捷、下单流畅、高并发下不超卖 |
| 商家 | 提供商品的商家 | 库存管理方便、收益清晰、对账准确 |
| 系统管理员 | 运维人员 | 系统稳定、监控完善、异常可追溯 |

### 1.3 核心业务流程

#### 流程1：用户充值流程（同步）
```
用户发起充值 → 验证金额 → 检查幂等性 → 更新余额 → 记录流水 → 发布充值成功事件 → 返回结果
```

**关键点**：
- 充值金额范围：0.01 ~ 1,000元（日常场景）/ 10,000元（压力测试场景）
- 必须支持幂等性（requestId去重）
- 发布领域事件通知其他模块

---

#### 流程2：商家添加库存流程（同步）
```
商家发起添加 → 验证SKU格式 → 验证价格/数量 → 创建或累加 → 发布库存变更事件 → 返回结果
```

**关键点**：
- SKU格式：`^[A-Z0-9_]+$`
- 同一商家下SKU唯一
- 发布领域事件供其他模块订阅

---

#### 流程3：用户下单购买流程（事件驱动 - 核心）

**传统同步方案的问题**：
- ❌ 事务持有锁时间长，并发性能差
- ❌ 领域间紧耦合，难以扩展
- ❌ 无法异步处理非核心逻辑

**事件驱动方案（推荐）**：
```
【阶段1：订单创建 - 同步事务】
用户发起下单 → 开启事务 → 验证库存和余额 → 创建订单(CREATED) 
→ 发布OrderCreatedEvent → 提交事务 → 返回订单ID

【阶段2：资金扣减 - 异步事件处理】
监听OrderCreatedEvent → 开启新事务 → 扣减用户余额 → 记录扣款流水 
→ 发布UserBalanceDeductedEvent → 提交事务

【阶段3：库存扣减与收款 - 异步事件处理】
监听UserBalanceDeductedEvent → 开启新事务 → 扣减库存 → 增加商家余额 
→ 记录收款流水 → 发布InventoryDeductedEvent → 提交事务

【阶段4：订单完成 - 异步事件处理】
监听InventoryDeductedEvent → 开启新事务 → 更新订单状态为COMPLETED 
→ 发布OrderCompletedEvent → 提交事务

【异常补偿流程】
如果任一步骤失败：
  → 发布OrderFailedEvent
  → 监听器执行补偿操作（退款、恢复库存）
  → 更新订单状态为FAILED
```

**优势**：
- ✅ 缩短事务持有锁时间，提升并发性能
- ✅ 领域间通过事件解耦，易于扩展
- ✅ 支持异步处理，响应更快
- ✅ 完善的补偿机制保证最终一致性

---

#### 流程4：商家每日结算对账流程
```
定时任务触发（每天02:00，选择低峰期避免影响正常业务） → 遍历商家 → 统计销售总额 → 统计收款总额 
→ 对比金额 → 生成对账记录 → 不一致则告警
```

## 二、领域建模（核心）

### 2.1 限界上下文划分

采用DDD领域驱动设计，将系统划分为三个限界上下文，通过**包路径**进行物理隔离，通过**Spring Event**进行逻辑解耦：

```
com.example.tradesystem
├── user（用户上下文）
├── merchant（商家上下文）
└── trade（交易上下文）
```

#### 2.1.1 用户上下文（User Context）

**职责边界**：
- 管理用户预存账户
- 处理账户充值
- 管理充值记录
- 监听订单事件并扣减余额

**发布的领域事件**：
- `UserBalanceDeductedEvent`：用户余额扣减成功
- `UserBalanceRefundedEvent`：用户余额退款成功

**监听的领域事件**：
- `OrderCreatedEvent`：订单创建成功，需要扣减余额
- `OrderFailedEvent`：订单失败，需要退款

---

#### 2.1.2 商家上下文（Merchant Context）

**职责边界**：
- 管理商家账户
- 管理商品库存（SKU维度）
- 处理库存添加
- 执行每日结算对账
- 监听订单事件并扣减库存、增加商家余额

**发布的领域事件**：
- `InventoryDeductedEvent`：库存扣减成功
- `StockRestoredEvent`：库存恢复成功

**监听的领域事件**：
- `UserBalanceDeductedEvent`：用户余额已扣减，需要扣减库存
- `OrderFailedEvent`：订单失败，需要恢复库存

---

#### 2.1.3 交易上下文（Trade Context）

**职责边界**：
- 管理订单生命周期
- 协调交易流程（发布事件）
- 订单查询
- 监听所有事件并更新订单状态

**发布的领域事件**：
- `OrderCreatedEvent`：订单创建成功
- `OrderCompletedEvent`：订单完成
- `OrderFailedEvent`：订单失败

**监听的领域事件**：
- `InventoryDeductedEvent`：库存已扣减，更新订单为COMPLETED
- 任何失败事件：更新订单为FAILED

### 2.2 聚合根设计

#### 2.2.1 用户上下文聚合根

**聚合根：UserAccount（用户账户）**

```java
package com.example.tradesystem.user.domain.model;

public class UserAccount {
    private Long userId;              // 用户ID（主键）
    private Money balance;            // 余额（值对象）
    private Integer version;          // 乐观锁版本号
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
    
    // 业务方法
    public void recharge(Money amount) {
        if (!amount.isPositive()) {
            throw new IllegalArgumentException("充值金额必须大于0");
        }
        this.balance = this.balance.add(amount);
        this.updatedAt = LocalDateTime.now();
    }
    
    public void deduct(Money amount) {
        if (!amount.isPositive()) {
            throw new IllegalArgumentException("扣款金额必须大于0");
        }
        if (this.balance.compareTo(amount) < 0) {
            throw new InsufficientBalanceException("余额不足");
        }
        this.balance = this.balance.subtract(amount);
        this.updatedAt = LocalDateTime.now();
    }
    
    public void refund(Money amount) {
        this.balance = this.balance.add(amount);
        this.updatedAt = LocalDateTime.now();
    }
}
```

```java
package com.example.tradesystem.merchant.domain.model;

public class ProductInventory {
    private Long id;
    private Long merchantId;
    private String sku;
    private String productName;
    private Money price;
    private Integer stockQuantity;
    private Integer soldQuantity;
    private Integer version;          // 乐观锁
    
    public void addStock(Integer quantity) {
        if (quantity <= 0) {
            throw new IllegalArgumentException("库存数量必须大于0");
        }
        this.stockQuantity += quantity;
    }
    
    public void deductStock(Integer quantity) {
        if (quantity <= 0) {
            throw new IllegalArgumentException("扣减数量必须大于0");
        }
        if (this.stockQuantity < quantity) {
            throw new InsufficientStockException("库存不足");
        }
        this.stockQuantity -= quantity;
        this.soldQuantity += quantity;
    }
    
    public void restoreStock(Integer quantity) {
        this.stockQuantity += quantity;
        this.soldQuantity -= quantity;
    }
    
    public boolean isStockSufficient(Integer quantity) {
        return this.stockQuantity >= quantity;
    }
}
```

```java
package com.example.tradesystem.common.event;

import lombok.Getter;
import org.springframework.context.ApplicationEvent;
import java.time.LocalDateTime;

@Getter
public abstract class DomainEvent extends ApplicationEvent {
    private final String eventId;           // 事件ID（UUID）
    private final LocalDateTime occurredAt; // 发生时间
    private final String eventType;         // 事件类型
    
    public DomainEvent(Object source, String eventType) {
        super(source);
        this.eventId = UUID.randomUUID().toString();
        this.occurredAt = LocalDateTime.now();
        this.eventType = eventType;
    }
}
```

```java
package com.example.tradesystem.trade.application.service;

@Service
@Transactional
public class OrderService {
    
    @Autowired
    private OrderMapper orderMapper;
    
    @Autowired
    private UserAccountMapper userAccountMapper;
    
    @Autowired
    private ProductInventoryMapper productInventoryMapper;
    
    @Autowired
    private ApplicationEventPublisher eventPublisher;
    
    /**
     * 创建订单（阶段1：同步事务）
     * 只负责验证和创建订单，不直接操作余额和库存
     */
    public Order createOrder(CreateOrderRequest request) {
        // 1. 查询用户账户（带行锁）
        UserAccount user = userAccountMapper.selectForUpdate(request.getUserId());
        if (user == null) {
            throw new UserNotFoundException("用户不存在");
        }
        
        // 2. 查询商品库存（带行锁）
        ProductInventory inventory = productInventoryMapper.selectBySkuForUpdate(request.getSku());
        if (inventory == null) {
            throw new ProductNotFoundException("商品不存在");
        }
        
        // 3. 验证库存充足
        if (!inventory.isStockSufficient(request.getQuantity())) {
            throw new InsufficientStockException("库存不足");
        }
        
        // 4. 计算订单金额
        Money totalAmount = inventory.getPrice().multiply(request.getQuantity());
        
        // 5. 验证余额充足
        if (user.getBalance().compareTo(totalAmount) < 0) {
            throw new InsufficientBalanceException("余额不足");
        }
        
        // 6. 创建订单（状态=CREATED）
        String orderId = UUID.randomUUID().toString().replace("-", "").toUpperCase();
        Order order = new Order(orderId, request.getUserId(), request.getMerchantId(), totalAmount);
        OrderItem item = new OrderItem(
            inventory.getSku(),
            inventory.getProductName(),
            request.getQuantity(),
            inventory.getPrice()
        );
        order.addItem(item);
        
        // 7. 保存订单到数据库
        orderMapper.insert(order);
        order.getItems().forEach(item -> orderMapper.insertOrderItem(orderId, item));
        
        // 8. 发布订单创建事件（异步处理后续逻辑）
        OrderCreatedEvent event = new OrderCreatedEvent(
            order.getOrderId(),
            order.getUserId(),
            order.getMerchantId(),
            convertToDTO(order.getItems()),
            order.getTotalAmount()
        );
        eventPublisher.publishEvent(event);
        
        log.info("订单创建成功，发布OrderCreatedEvent: {}", order.getOrderId());
        
        return order;
    }
}
```

```java
package com.example.tradesystem.user.application.listener;

@Component
@Slf4j
public class UserBalanceEventListener {
    
    @Autowired
    private UserAccountMapper userAccountMapper;
    
    @Autowired
    private RechargeRecordMapper rechargeRecordMapper;
    
    @Autowired
    private ApplicationEventPublisher eventPublisher;
    
    /**
     * 监听订单创建事件，扣减用户余额（阶段2）
     * 支持乐观锁冲突重试机制
     */
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    @Transactional
    public void handleOrderCreated(OrderCreatedEvent event) {
        int maxRetries = 3;
        for (int retryCount = 0; retryCount < maxRetries; retryCount++) {
            try {
                log.info("收到OrderCreatedEvent，开始扣减用户余额: orderId={}, retry={}", 
                    event.getOrderId(), retryCount);
                
                // 1. 查询用户账户
                UserAccount user = userAccountMapper.selectById(event.getUserId());
                if (user == null) {
                    throw new UserNotFoundException("用户不存在");
                }
                
                // 2. 扣减余额（使用乐观锁）
                int updatedRows = userAccountMapper.deductBalanceWithVersion(
                    event.getUserId(),
                    event.getTotalAmount().getAmount(),
                    user.getVersion()
                );
                
                if (updatedRows == 0) {
                    if (retryCount < maxRetries - 1) {
                        // 非最后一次重试，等待后重试（指数退避）
                        long waitTime = (long) Math.pow(2, retryCount) * 100; // 100ms, 200ms, 400ms
                        log.warn("余额扣减失败（乐观锁冲突），{}ms后重试: orderId={}", 
                            waitTime, event.getOrderId());
                        Thread.sleep(waitTime);
                        continue;
                    } else {
                        // 最后一次重试仍失败，抛出异常
                        throw new OptimisticLockException("余额扣减失败，并发冲突，已重试" + maxRetries + "次");
                    }
                }
                
                // 3. 记录扣款流水
                String deductionRecordId = UUID.randomUUID().toString().replace("-", "").toUpperCase();
                rechargeRecordMapper.insertDeductionRecord(deductionRecordId, event);
                
                // 4. 发布余额扣减成功事件
                UserBalanceDeductedEvent balanceEvent = new UserBalanceDeductedEvent(
                    event.getOrderId(),
                    event.getUserId(),
                    event.getTotalAmount(),
                    deductionRecordId
                );
                eventPublisher.publishEvent(balanceEvent);
                
                log.info("用户余额扣减成功: userId={}, orderId={}", event.getUserId(), event.getOrderId());
                return; // 成功，退出重试循环
                
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                log.error("重试被中断: orderId={}", event.getOrderId(), e);
                throw new RuntimeException("余额扣减被中断", e);
            } catch (Exception e) {
                log.error("用户余额扣减失败: orderId={}, retry={}/{}", 
                    event.getOrderId(), retryCount + 1, maxRetries, e);
                
                if (retryCount == maxRetries - 1) {
                    // 最后一次失败，发布订单失败事件，触发补偿
                    OrderFailedEvent failedEvent = new OrderFailedEvent(
                        event.getOrderId(),
                        "用户余额扣减失败: " + e.getMessage(),
                        OrderFailedEvent.FailedStage.BALANCE_DEDUCTION
                    );
                    eventPublisher.publishEvent(failedEvent);
                }
                // 非最后一次失败，继续重试
            }
        }
    }
    
    /**
     * 监听订单失败事件，退款（补偿）
     * 保证幂等性：通过补偿流水表防止重复退款
     */
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    @Transactional
    public void handleOrderFailed(OrderFailedEvent event) {
        if (event.getFailedStage() == OrderFailedEvent.FailedStage.BALANCE_DEDUCTION) {
            // 余额扣减阶段失败，无需退款
            log.info("余额扣减阶段失败，无需退款: orderId={}", event.getOrderId());
            return;
        }
        
        try {
            log.info("收到OrderFailedEvent，开始退款: orderId={}", event.getOrderId());
            
            // 1. 检查是否已补偿（幂等性）
            if (compensationRecordRepository.existsByOrderIdAndType(
                event.getOrderId(), CompensationType.REFUND)) {
                log.info("退款已执行，跳过: orderId={}", event.getOrderId());
                return;
            }
            
            // 2. 查询扣款记录，获取退款金额
            DeductionRecord deductionRecord = rechargeRecordMapper.selectByOrderId(event.getOrderId());
            if (deductionRecord == null) {
                log.error("未找到扣款记录，无法退款: orderId={}", event.getOrderId());
                throw new BusinessException("未找到扣款记录");
            }
            
            // 3. 执行退款（增加用户余额）
            UserAccount user = userAccountMapper.selectById(deductionRecord.getUserId());
            if (user == null) {
                throw new UserNotFoundException("用户不存在");
            }
            
            int refundRows = userAccountMapper.creditBalanceWithVersion(
                user.getUserId(),
                deductionRecord.getAmount(),
                user.getVersion()
            );
            
            if (refundRows == 0) {
                throw new OptimisticLockException("退款失败，并发冲突");
            }
            
            // 4. 记录退款流水
            String refundRecordId = UUID.randomUUID().toString().replace("-", "").toUpperCase();
            rechargeRecordMapper.insertRefundRecord(refundRecordId, event.getOrderId(), 
                user.getUserId(), deductionRecord.getAmount());
            
            // 5. 记录补偿流水（幂等性保证）
            compensationRecordRepository.save(new CompensationRecord(
                event.getOrderId(),
                CompensationType.REFUND,
                refundRecordId,
                CompensationStatus.SUCCESS
            ));
            
            // 6. 发布退款成功事件
            UserBalanceRefundedEvent refundedEvent = new UserBalanceRefundedEvent(
                event.getOrderId(),
                user.getUserId(),
                deductionRecord.getAmount()
            );
            eventPublisher.publishEvent(refundedEvent);
            
            log.info("退款成功: orderId={}, amount={}", event.getOrderId(), deductionRecord.getAmount());
            
        } catch (Exception e) {
            log.error("退款失败: orderId={}", event.getOrderId(), e);
            
            // 记录补偿失败，人工介入
            compensationRecordRepository.save(new CompensationRecord(
                event.getOrderId(),
                CompensationType.REFUND,
                null,
                CompensationStatus.FAILED,
                e.getMessage()
            ));
            
            // 发送告警
            alertService.sendAlert("退款补偿失败", 
                "订单ID: " + event.getOrderId() + ", 错误: " + e.getMessage());
        }
    }
}
```

```java
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                log.error("重试被中断: orderId={}", event.getOrderId(), e);
                throw new RuntimeException("订单状态更新被中断", e);
            } catch (Exception e) {
                log.error("更新订单状态失败: orderId={}, retry={}/{}", 
                    event.getOrderId(), retryCount + 1, maxRetries, e);
                
                if (retryCount == maxRetries - 1) {
                    // 最后一次失败，记录异常，人工介入
                    exceptionRecordRepository.save(new ExceptionRecord(
                        event.getOrderId(),
                        "ORDER_STATUS_UPDATE_FAILED",
                        e.getMessage(),
                        LocalDateTime.now()
                    ));
                    
                    // 发送告警
                    alertService.sendAlert("订单失败状态更新失败", 
                        "订单ID: " + event.getOrderId() + ", 错误: " + e.getMessage());
                }
            }
        }
    }
}
```

### 4.3 关键技术决策

#### 决策1：为什么用事件驱动？

**优势**：
- 领域间解耦：通过事件通信，不直接调用
- 异步处理：提升响应速度
- 易于扩展：新增业务只需添加监听器
- 高并发优化：缩短事务持有锁时间

**劣势**：
- 调试复杂：事件链路长
- 最终一致性：需要补偿机制

---

#### 决策2：如何保证事件不丢失？

**问题分析**：
Spring Event是内存中的事件机制，应用重启会导致未处理的事件丢失。例如：
- 如果阶段1发布OrderCreatedEvent后立即重启，后续阶段永远不会执行
- 订单将永远停留在CREATED状态，用户余额已扣减但库存未扣减
- 造成数据不一致，影响用户体验和账务准确性

**方案**：
1. **事务绑定**：使用`@TransactionalEventListener(phase = AFTER_COMMIT)`确保事务提交后才发布事件
   - 避免事务回滚后事件仍被消费的问题
   
2. **事件持久化（推荐）**：关键事件保存到`domain_event_record`表，支持事件回溯和重放
   ```java
   // 在发布事件前持久化
   eventRecordRepository.save(new EventRecord(event.getEventId(), "PENDING"));
   eventPublisher.publishEvent(event);
   
   // 监听器处理完成后更新状态
   eventRecordRepository.updateStatus(event.getEventId(), "PROCESSED");
   
   // 定时任务扫描PENDING状态的事件，超过阈值则重发
   @Scheduled(fixedDelay = 60000) // 每分钟检查一次
   public void retryPendingEvents() {
       List<EventRecord> pendingEvents = eventRecordRepository.findPendingEvents();
       for (EventRecord record : pendingEvents) {
           if (record.getCreatedAt().plusMinutes(5).isBefore(LocalDateTime.now())) {
               log.warn("事件处理超时，准备重发: eventId={}", record.getEventId());
               // 重发逻辑...
           }
       }
   }
   ```
   
3. **重试机制**：监听器内部捕获异常，最多重试3次（指数退避）
   - 详见代码示例中的重试逻辑
   
4. **对账补偿**：T+1对账发现不一致，人工介入处理
   - 每天凌晨02:00执行对账任务
   - 对比订单、流水、账户余额的一致性
   
5. **迁移方案**：生产环境建议迁移到RabbitMQ/Kafka，提供消息持久化和ACK机制
   - Spring Event适合单体应用的开发和学习场景
   - 生产环境推荐使用分布式消息队列保证可靠性
   - 迁移成本低：只需替换EventPublisher为RabbitTemplate/KafkaTemplate

---

#### 决策3：如何处理事件顺序性？

**方案**：
1. **事件链式设计**：每个事件触发下一个事件
2. **阶段标记**：订单状态标记当前处理阶段
3. **幂等性**：监听器支持重复消费

```java
 * 限流注解
 * 用于标记需要限流的接口

     */
    long timeout() default 1;
    
    /**
     * 限流提示信息
     */
    String message() default "系统繁忙，请稍后重试";
```

**实现步骤2：限流拦截器**

```java
package com.example.tradesystem.common.interceptor;

import com.example.tradesystem.common.annotation.RateLimit;
import com.example.tradesystem.common.response.ApiResponse;
import com.google.common.util.concurrent.RateLimiter;
import lombok.extern.slf4j.Slf4j;
import org.springframework.expression.EvaluationContext;
import org.springframework.expression.ExpressionParser;
import org.springframework.expression.spel.standard.SpelExpressionParser;
import org.springframework.expression.spel.support.StandardEvaluationContext;
import org.springframework.stereotype.Component;
import org.springframework.web.method.HandlerMethod;
import org.springframework.web.servlet.HandlerInterceptor;

import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.lang.reflect.Method;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.TimeUnit;

/**
 * 限流拦截器
 * 拦截带有@RateLimit注解的方法，执行限流逻辑
 */
@Component
@Slf4j
public class RateLimitInterceptor implements HandlerInterceptor {
    
    /**
     * 限流器缓存：key -> RateLimiter
     * 注意：ConcurrentHashMap保证线程安全，多个线程同时访问同一个key时，
     * computeIfAbsent保证原子性操作，不会创建多个RateLimiter实例
     */
    private final ConcurrentHashMap<String, RateLimiter> limiterMap = new ConcurrentHashMap<>();
    
    /**
     * SpEL表达式解析器（线程安全，可复用）
     * 注意：Expression对象是线程安全的，可以缓存复用，避免重复解析提升性能
     */
    private final ExpressionParser parser = new SpelExpressionParser();
    
    /**
     * 编译后的SpEL表达式缓存
     * key: 表达式字符串, value: 编译后的Expression对象
     * 在500 TPS高并发场景下，缓存可显著减少解析开销
     */
    private final ConcurrentHashMap<String, org.springframework.expression.Expression> expressionCache = 
        new ConcurrentHashMap<>();
    
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) 
            throws Exception {
        
        // 只处理方法级别的请求
        if (!(handler instanceof HandlerMethod)) {
            return true;
        }
        
        HandlerMethod handlerMethod = (HandlerMethod) handler;
        Method method = handlerMethod.getMethod();
        
        // 检查方法是否有@RateLimit注解
        RateLimit rateLimit = method.getAnnotation(RateLimit.class);
        if (rateLimit == null) {
            return true;
        }
        
        // 构建限流key
        String limitKey = buildLimitKey(rateLimit.key(), request, handlerMethod);
        
        // 获取或创建限流器
        RateLimiter limiter = limiterMap.computeIfAbsent(limitKey, k -> 
            RateLimiter.create(rateLimit.permitsPerSecond())
        );
        
        // 尝试获取令牌
        if (!limiter.tryAcquire(rateLimit.timeout(), TimeUnit.SECONDS)) {
            log.warn("触发限流: key={}, uri={}, method={}", 
                limitKey, request.getRequestURI(), method.getName());
            
            // 返回429错误
            writeRateLimitResponse(response, rateLimit.message());
            return false;
        }
        
        return true;
    }
    
    /**
     * 构建限流key
     * 支持静态key和动态SpEL表达式
     */
    private String buildLimitKey(String keyTemplate, HttpServletRequest request, 
                                  HandlerMethod handlerMethod) {
        if (keyTemplate == null || keyTemplate.isEmpty()) {
            // 默认使用URI作为key
            return "uri:" + request.getRequestURI();
        }
        
        // 如果包含SpEL表达式，则解析
        if (keyTemplate.contains("#{")) {
            return parseSpEL(keyTemplate, request, handlerMethod);
        }
        
        return keyTemplate;
    }
    
    /**
     * 解析SpEL表达式（带缓存优化）
     */
    private String parseSpEL(String expression, HttpServletRequest request, 
                             HandlerMethod handlerMethod) {
        try {
            // 从缓存获取或编译表达式（线程安全）
            org.springframework.expression.Expression compiledExpression = 
                expressionCache.computeIfAbsent(expression, expr -> parser.parseExpression(expr));
            
            EvaluationContext context = new StandardEvaluationContext();
            
            // 可以添加更多上下文变量
            context.setVariable("request", request);
            
            // 执行已编译的表达式
            return compiledExpression.getValue(context, String.class);
        } catch (Exception e) {
            log.error("SpEL表达式解析失败: {}", expression, e);
            return "default:" + request.getRequestURI();
        }
    }
    
    /**
     * 写入限流响应
     */
    private void writeRateLimitResponse(HttpServletResponse response, String message) 
            throws IOException {
        response.setStatus(429);
        response.setContentType("application/json;charset=UTF-8");
        response.setHeader("Retry-After", "5");
        
        ApiResponse<?> apiResponse = ApiResponse.error(429, message);
        response.getWriter().write(
            new com.fasterxml.jackson.databind.ObjectMapper()
                .writeValueAsString(apiResponse)
        );
    }
}
```

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {
    
    @Autowired
    private RateLimitInterceptor rateLimitInterceptor;
    
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        // 注册限流拦截器
        registry.addInterceptor(rateLimitInterceptor)
                .addPathPatterns("/api/v1/**")  // 拦截所有API请求
                .excludePathPatterns(           // 排除不需要限流的接口
                    "/api/v1/health",
                    "/api/v1/docs/**"
                );
    }
}
```

```java
package com.example.tradesystem.common.monitor;

import io.micrometer.core.instrument.MeterRegistry;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;

@Component
@Slf4j
public class RateLimitMonitor {
    
    private final MeterRegistry meterRegistry;
    
    public RateLimitMonitor(MeterRegistry meterRegistry) {
        this.meterRegistry = meterRegistry;
    }
    
    /**
     * 记录限流事件
     */
    public void recordRateLimit(String apiKey, String userId) {
        // 增加限流计数
```

#### 7.1.4 补偿机制监控（新增）

**关键监控指标**：

```java
package com.example.tradesystem.common.monitor;

import io.micrometer.core.instrument.MeterRegistry;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;

@Component
@Slf4j
public class CompensationMonitor {
    
    private final MeterRegistry meterRegistry;
    
    public CompensationMonitor(MeterRegistry meterRegistry) {
        this.meterRegistry = meterRegistry;
    }
    
    /**
     * 记录补偿成功
     */
    public void recordCompensationSuccess(String compensationType, String orderId) {
        meterRegistry.counter("compensation.success", 
            "type", compensationType,
            "order_id", orderId
        ).increment();
        
        log.info("补偿成功: type={}, orderId={}", compensationType, orderId);
    }
    
    /**
     * 记录补偿失败
     */
    public void recordCompensationFailure(String compensationType, String orderId, String error) {
        meterRegistry.counter("compensation.failure", 
            "type", compensationType,
            "order_id", orderId,
            "error", error
        ).increment();
        
        log.error("补偿失败: type={}, orderId={}, error={}", compensationType, orderId, error);
        
        // 发送告警
        if (shouldAlert(compensationType)) {
            alertService.sendAlert("补偿失败告警", 
                String.format("补偿类型: %s, 订单ID: %s, 错误: %s", 
                    compensationType, orderId, error));
        }
    }
    
    /**
     * 判断是否需要告警（补偿失败率 > 5% 时告警）
     */
    private boolean shouldAlert(String compensationType) {
        double successCount = meterRegistry.counter("compensation.success", "type", compensationType).count();
        double failureCount = meterRegistry.counter("compensation.failure", "type", compensationType).count();
        
        if (successCount + failureCount == 0) {
            return false;
        }
        
        double failureRate = failureCount / (successCount + failureCount);
        return failureRate > 0.05; // 失败率超过5%
    }
}
```

#### 7.2.3 超时兜底机制（新增）

**问题**：订单可能长时间停留在CREATED状态，前端轮询会一直显示“处理中”

**解决方案**：定时任务扫描超时订单，强制标记为FAILED并触发补偿

```java
package com.example.tradesystem.trade.application.job;

@Component
@Slf4j
public class OrderTimeoutJob {
    
    @Autowired
    private OrderMapper orderMapper;
    
    @Autowired
    private ApplicationEventPublisher eventPublisher;
    
    /**
     * 每5分钟执行一次，扫描30分钟未完成的订单
     */
    @Scheduled(fixedRate = 5 * 60 * 1000)
    @Transactional
    public void checkTimeoutOrders() {
        log.info("开始扫描超时订单...");
        
        // 查询30分钟前创建且状态仍为CREATED的订单
        LocalDateTime timeoutThreshold = LocalDateTime.now().minusMinutes(30);
        List<Order> timeoutOrders = orderMapper.selectTimeoutOrders(
            OrderStatus.CREATED, 
            timeoutThreshold
        );
        
        if (timeoutOrders.isEmpty()) {
            log.info("无超时订单");
            return;
        }
        
        log.warn("发现{}个超时订单，开始处理...", timeoutOrders.size());
        
        for (Order order : timeoutOrders) {
            try {
                log.warn("订单超时，强制标记为FAILED: orderId={}, createTime={}", 
                    order.getOrderId(), order.getCreateTime());
                
                // 更新订单状态为FAILED
                order.markAsFailed("订单处理超时（30分钟）");
                orderMapper.updateStatus(order.getOrderId(), order.getStatus(), null);
                
                // 发布订单失败事件，触发补偿
                OrderFailedEvent failedEvent = new OrderFailedEvent(
                    order.getOrderId(),
                    "订单处理超时",
                    OrderFailedEvent.FailedStage.INVENTORY_DEDUCTION // 假设在库存扣减阶段超时
                );
                eventPublisher.publishEvent(failedEvent);
                
                log.info("超时订单处理完成: orderId={}", order.getOrderId());
                
            } catch (Exception e) {
                log.error("超时订单处理失败: orderId={}", order.getOrderId(), e);
                // 记录异常，人工介入
            }
        }
    }
}
```
